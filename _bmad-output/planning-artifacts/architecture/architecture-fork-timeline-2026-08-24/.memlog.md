- (constraint) AD-30 (hérité, master spine) : l'état vit hors de tout ce qui est remplaçable — read-only, réutilisé : deux branches divergent sans se contaminer.
- (constraint) AD-31 (hérité) : un remplacement prend ou rend la main, rollback restaure la version précédente avec ses enfants — read-only, base du hot-swap sur branche.
- (constraint) AD-33 (hérité) : un run est rejouable depuis son seul flux — read-only, base du rejeu jusqu'à N (sequence adressable).
- (constraint) Garde-fou d'honnêteté 1 : le rollback est intra-runtime, il ne défait pas un effet externe. Prévenir avant (porte + sandbox), pas réparer après.
- (constraint) Garde-fou d'honnêteté 2 : primitive (réversibilité + fork visuel), jamais 'plateforme de fiabilité' ni 'control plane'.
- (question) Quel format de trace externe en premier ? [ASSUMPTION] : un schéma canonique interne 'AgentTrace' + un adaptateur LangGraph d'abord (le plus screené), OTLP ensuite.

- (question) Déterminisme de la branche : une re-exécution avec modèle n'est pas rejouable à l'identique. [ASSUMPTION] : la branche est elle-même enregistrée en flux (AD-33) dès son premier pas, donc rejouable après coup, mais pas identique au tronc.

- (decision) Réalité (F9-F11) : une TRACE d'observabilité n'est pas un CHECKPOINT reprenable. Re-exécuter un agent LangGraph exige checkpointer+graphe+outils+modèle, pas une trace ; le Worker a le réseau retiré (AD-29). DONC : v1 = le tronc est une VISUALISATION de la trace importée ; la branche re-exécute d'abord des COMPORTEMENTS MAISON (source dans le flux), la re-exécution d'agents étrangers (via checkpoint, runner réseau-gated) passe en Deferred. AD-37/AD-35 corrigés.
- (decision) Identité (F1,F2,F6) : clé d'événement post-fork = (branchId, sequence) ; branchId minté par le runtime, opaque, indépendant de N ; un événement 'branch-forked' (1er de la branche) porte {trunkId, N} — référencer un recording immuable par id+N est permis (nuance AD-33).
- (decision) Préfixe partagé (F5) : seul le TABLEAU d'événements [1..N] est partagé et immuable ; chaque branche RE-RÉDUIT ce préfixe dans son propre read model ; aucun read model vivant partagé (concilie AD-36 et AD-38).
- (decision) Temps (F4) : le 'at' de la branche est élapsé-depuis-le-fork, plus un offset de fork enregistré, pour aligner l'axe des deux panneaux.
- (decision) Teardown (F7,F8) : le tronc est un store-sans-kernel (recording, AD-37), pas une branche. Rejeter une branche = teardown entier (kernel+store+session), distinct du rollback composant d'AD-31.
- (decision) Hydratation (F13) : nouvel invariant — matérialiser un kernel vivant depuis le préfixe (ré-instancier les composants vivants à N, restaurer identité/parentage pour qu'AD-31 'restore with children' tienne). C'est LE mécanisme neuf load-bearing.
- (decision) Éval (F12) : la comparaison diffe deux RunMeasure (pas Report, qui est un agrégat de population n>1) ; un tronc importé n'a pas nos événements de cycle de vie, donc l'adaptateur doit les mapper ou la mesure est adaptée. Nom corrigé measure->RunMeasure.
