- (direction) Voie rapide retenue : Guillaume a donné carte blanche après le PRD, en demandant le résultat le plus complet possible. Les inférences sont taguées [ASSUMPTION] dans la spine.
- (constraint) Le PRD finalisé du 2026-08-20 est la source d'exigences : 62 FR, 23 NFR, client-only, aucun token par défaut, aucun décor visuel.
- (constraint) Le spike du 2026-08-20 a prouvé dans Chrome : bundle Vite sans API Node, réversion en ordre inverse, cascade, coeffect réactif, fabrication de composant à l'exécution, introspection du registre.
- (constraint) CSP stricte sans unsafe-eval : new Function échoue, mesuré. La fabrication par composition est la seule voie utilisable en mode par défaut.
- (version) Versions vérifiées sur le registre npm le 2026-08-20 : vue 3.5.41, vite 8.2.2, cordis 4.0.0-rc.8, vitest 4.1.11, playwright 1.62.1, elkjs 0.12.0, dagre 0.8.5, @dagrejs/dagre 3.1.1, @vue-flow/core 1.48.2, pinia 4.0.3.
- (decision) Paradigme : noyau de composition + projection unidirectionnelle. Le runtime Cordis est le cœur ; l'interface n'en lit jamais l'état, elle consomme un flux d'événements typés projeté dans un modèle de lecture. Empêche que l'interface et le moteur deviennent deux propriétaires du même état, et rend l'invariant C3 du PRD testable.
- (decision) Le module runtime est le seul autorisé à importer cordis. Contrôlé par une règle de lint, pas par la discipline. Empêche que des appels au moteur se dispersent dans les composants Vue.
- (decision) Le graphe est une projection, jamais une source. Aucun composant d'interface ne crée de nœud ni d'arête. Empêche le nœud décoratif interdit par FR-016 et la contre-métrique C6.
- (decision) Canal unique : tout ce que l'interface sait du run arrive par une union discriminée RunEvent. Pas de rappel ad hoc, pas d'accès direct au registre. Empêche deux chemins de mise à jour concurrents.
- (decision) Le store de run n'est écrit que par le réducteur d'événements. Les composants Vue sont en lecture seule sur lui. Empêche deux propriétaires d'une même donnée.
- (decision) Contrat de composant unique pour agents et outils : name, inject, provide, apply, plus des métadonnées de présentation. La technologie n'est déclarée que si le composant l'exécute réellement, conformément à FR-057.
- (decision) L'identité des composants appartient au runtime : l'identifiant vient de la fiber. L'interface ne fabrique jamais d'identifiant. Empêche deux schémas d'identité.
- (decision) La fabrication à l'exécution passe par un port Fabrique avec deux implémentations : par composition de primitives (défaut, compatible CSP stricte) et par évaluation de code (réservée au mode LLM branché). Empêche que l'évaluation de code s'infiltre dans le chemin par défaut.
- (decision) Le LLM est un adaptateur derrière un port Raisonneur, fourni comme coeffect. L'implémentation déterministe est le défaut. Empêche des appels au modèle dispersés dans les agents et rend le repli de FR-046 mécanique.
- (decision) Un scénario est une donnée pure : il ne peut importer ni code d'interface ni code de runtime, il déclare. Empêche les branchements conditionnels par scénario dans le moteur, exigés par FR-050.
- (decision) La disposition du graphe est calculée par un algorithme en couches maison, dérivé de la profondeur topologique des coeffects, sans dépendance externe. Même topologie, même disposition. Empêche le tremblement entre deux rendus et évite d'ajouter elkjs (lourd, contraire à NFR-007).
- (decision) Aucune bibliothèque de graphe ni de store externe : pas de Vue Flow, pas de Pinia, pas de dagre. Rendu SVG direct et store maison à réducteur. Le graphe fait quarante nœuds au plus et le design impose un rendu sur mesure ; une dépendance apporterait son paradigme et son poids sans rien résoudre.
- (decision) Le vérificateur d'allégations est un moteur de règles pur : sans horloge, sans aléatoire, sans entrée/sortie. Empêche la dérive de FR-039 et rend le déterminisme testable.
- (decision) Aucun secret n'est persisté : la clé d'API vit dans une variable de module, jamais dans localStorage ni sessionStorage, jamais journalisée. Empêche une fuite par le stockage du navigateur.
- (decision) La télémétrie est un module unique qui n'expose que quatre appels nommés et refuse toute charge utile libre. Empêche que du contenu utilisateur parte par inadvertance.
- (decision) Un composant qui échoue devient un événement d'erreur, jamais une exception qui remonte : le run continue. Empêche qu'un agent défaillant fasse tomber la démonstration.
- (decision) Le déploiement sert un build statique derrière nginx avec une CSP stricte sans unsafe-eval, en cohérence avec NFR-023.
- (assumption) Le déplacement et le zoom du canvas sont implémentés à la main sur le SVG (transformation de vue), sans bibliothèque.
- (assumption) Les tests d'invariant tournent sous Vitest 4 en mode navigateur avec Playwright, comme le spike.
- (question) Le HMR réel (@cordisjs/plugin-hmr) n'est ni installé ni prouvé : FR-054 repose dessus ou sur un rechargement de composant équivalent.
- (question) La tenue à quarante nœuds vivants (NFR-002) n'est pas mesurée.
- (event) Passe adversariale du reviewer gate : cinq paires d'unités conformes à tous les AD mais incompatibles ont été construites, cinq trous fermés.
- (decision) AD-17 : un nom de coeffect a un propriétaire unique déclaré dans le scénario ; un second fournisseur est une erreur de chargement, pas un remplacement silencieux.
- (decision) AD-18 : un composant produit au plus un artefact final, indexé par son identifiant ; le réducteur ne garde que la dernière version. L'artefact d'un nœud est toujours défini et unique.
- (decision) AD-19 : l'état affiché d'un nœud est dérivé par une fonction unique dans etat/, à partir du FiberState et des événements. FiberState ne connaît pas la notion de terminé ; le composant émet travail-termine et seule cette fonction traduit.
- (decision) AD-20 : chaque événement porte un numéro de séquence monotone produit par le runtime ; la ligne de narration est la dérivation du message de plus haute séquence.
- (decision) AD-21 : les primitives de fabrication vivent dans un registre unique tenu par runtime/fabrique ; une primitive inconnue échoue à la compilation.
- (decision) AD-11 resserré : à l'intérieur d'une couche, les nœuds s'ordonnent par clé de déclaration du scénario, jamais par ordre d'arrivée. L'échappatoire de la première rédaction est fermée.
- (constraint) Vérification des versions : TypeScript 7.0.2 est disponible, le projet reste sur ~6.0.0. La montée n'est pas engagée par cette spine.
- (event) Réconciliation des entrées : deux manques trouvés face au PRD. L'enveloppe opérationnelle (déploiement, environnements, CSP servie) n'était pas couverte, et l'accessibilité (NFR-015 à NFR-018) tombait entre les mailles alors qu'elle diverge unité par unité.
- (decision) AD-22 : l'accessibilité est un invariant de rendu. Forme ou texte en plus de la couleur, clavier sur tout actionnable, animation neutralisable sans perte d'information, états de nœud rendus par un composant unique.
- (decision) Section déploiement ajoutée : build statique, image node22 vers nginx, VPS, CSP stricte servie et testée, aucune variable d'environnement dans le chemin par défaut, aucun secret dans l'image.

- (decision) AD-11 révisé après mesure : @dagrejs/dagre est retenu pour le calcul de coordonnées. Le rejet en bloc des bibliothèques de disposition était une erreur de jugement — écrire un Sugiyama correct coûte plus que 17,6 ko, et FR-022 est exactement ce que cet algorithme résout. elkjs reste rejeté (484 ko contre un budget total de 500), Vue Flow reste rejeté (bibliothèque de rendu, incompatible avec un design sur mesure), Pinia reste rejeté (le réducteur fait trente lignes).
- (decision) AD-11 renforcé : la disposition est calculée une seule fois au démarrage sur la topologie complète déclarée, emplacements réservés compris pour les composants fabriqués à l'exécution. Les nœuds sont révélés, jamais repositionnés. Empêche que les nœuds déjà posés sautent quand une pièce fabriquée arrive.
